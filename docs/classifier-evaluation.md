# Review classifier evaluation

Run `pnpm eval:classifier` from the repository root. The command loads local Next.js environment files with `@next/env`, then checks that `AI_GATEWAY_API_KEY` is present before it starts Promptfoo. With no key it exits with an explicit error and does not substitute a local model or canned output. The key stays in the process environment and is never added to the Promptfoo config or result file.

The custom provider calls the production `assessReview(review, location)` boundary in `src/lib/product/ai.ts`. It uses the configured Vercel AI Gateway classifier and returns the resulting assessment as JSON, including action, reasons, signals, confidence, model, and policy version. It is not a prompt-only replica or a GPT judge. Provider and model errors fail the eval instead of creating fallback assessments.

The cases in `evals/review-classifier/promptfooconfig.yaml` are synthetic development regression cases. They check specific routing expectations for generic praise, blank ratings, existing owner replies, questions, routine complaints, serious incidents, threats, hate, exposed private information, unrelated advertisements, and ambiguous wording. The two reported praise examples preserve the same review text at its captured four-star rating and at five stars. Cases with visible threats or likely policy violations accept either `report` or `human_review` where the classifier also flags the evidence; human escalation is appropriate when the model identifies serious consequences or missing facts. Assertions check the action and relevant signals; they do not measure general accuracy or represent a held-out benchmark with human labels. A change in the production decision policy may require updating an expectation after review.

Results are written to `.reviewguard-data/classifier-evals/live-latest.json` and `recorded-latest.json`, which are covered by the repository's existing ignore rule for `.reviewguard-data/`. The eval runs with caching disabled and disables Promptfoo telemetry, sharing, and update checks. Review result files as sensitive because they contain model outputs and input review text. The production assessment boundary does not expose Gateway token or billing usage, so Promptfoo reports no token/cost total for these live calls; this harness defines no accuracy threshold or cost target.

## Implementation notes

Promptfoo is pinned as a development dependency at `0.123.1`; this release requires Node.js `>=22.22.0`. The TypeScript custom provider imports the application modules directly and runs from the repository root, which lets Promptfoo resolve the project's TypeScript configuration. Promptfoo's documentation describes custom TypeScript providers for frontend projects and the `callApi` provider contract: [JavaScript and TypeScript providers](https://www.promptfoo.dev/docs/providers/custom-api/).

For local usage, keep `AI_GATEWAY_API_KEY` in the ignored `.env.local` file or export it in the current shell. Do not paste the key into a command argument. To check the missing-key behavior, run the command in an environment where neither the shell nor the local Next.js environment files supply `AI_GATEWAY_API_KEY`; unsetting the shell variable alone still loads the key from `.env.local`. The command should stop before launching Promptfoo. Do not include the resulting JSON file in commits or issue comments.
